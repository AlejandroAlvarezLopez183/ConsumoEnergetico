# Check-in diario (asincrónico, 5–10 minutos)

Cada colaborador lo publica en el canal acordado antes de la hora que el equipo defina.

```text
Fecha:
Responsable:
Issue / PR:

1. Ayer terminé:
- Resultado observable (enlace o captura):

2. Hoy terminaré:
- Un resultado concreto:
- Issue en el que trabajaré:

3. Bloqueo / decisión que necesito:
- Qué intenté:
- Qué necesito y de quién:

4. Riesgo o cambio de alcance:
- Ninguno / descripción:
```

## Reglas

- No escribir solo “trabajé en frontend” o “estuve con la IA”. Reportar un resultado.
- Enlazar issue o Pull Request.
- Si no hay avance por un bloqueo, indicarlo pronto; no inventar una tarea para parecer ocupado.
- Si el trabajo cambió de alcance, pausar y pedir decisión.
- El seguimiento diario es para detectar bloqueos, no para resolver arquitectura compleja en el chat.
